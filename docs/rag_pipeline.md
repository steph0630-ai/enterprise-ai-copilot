# RAG Pipeline 详解

> Day 3 重点：把"文件 → 知识"和"问题 → 答案"两条流水线彻底讲清楚。

## 总览

```
【上传】文件 → 解析 → 切分 → Embedding → 存向量库
【查询】问题 → Embedding → 向量搜索 → 找到相关片段 → 拼 Prompt → LLM 回答
```

## 三个核心概念

### ① Chunk（切分）
- 100 页文档不能直接给模型：①模型长度有限 ②检索不精准。
- 切成小段，每段叫 Chunk（报销范围 / 审批流程 / 金额限制）。
- 额外好处：更快、更省 token。

### ② Embedding（向量化）
- 把文字变成一串数字（向量），这串数字代表"意思"。
- 意思相近 → 向量挨得近；意思无关 → 向量离得远。
- 价值：**"字面不同但意思相近"也能搜到**（"出差"能搜到"差旅"）。
- 对比：关键词搜索 = 找字一样的；Embedding = 找意思一样的（语义检索）。

### ③ 向量数据库（Vector DB）
- 存的是向量，做的是"找最近邻"，不是"精确相等"。
- MySQL 只能 `= 精确匹配`，做不了语义检索 → 需要专门的向量库（pgvector / Milvus / Chroma）。
- 为什么需要索引：百万级向量里快速找最相似的，靠 ANN 近似最近邻搜索。

## 查询流水线（5 步，背下来）

```
⑤ 用户提问
① 问题向量化（Embedding）
② 向量搜索（找最近邻 chunk）
③ 拼 Prompt（问题 + 相关片段）
④ LLM 回答（生成自然语言）
```

## 关键：为什么问题和文档都要 Embedding？

> 因为两者都要变成"同一张语义地图上的坐标"，才能算"谁离谁近"。
> 类比：文档是标好的点，用户问题是"我站的位置"，向量搜索 = 找离我最近的点。

## 记忆锚点（三句话）

1. Chunk = 把书撕成书签，每张讲一件事。
2. Embedding = 把文字放进语义地图，意思近的住得近。
3. 向量库 = 按"离我最近"找邻居，不是按门牌号精确找人。
