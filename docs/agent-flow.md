# Agent 流程

## 工具循环

```text
用户问题
  |
  v
LLM 判断是否调用工具
  |-- search_knowledge -> RAG 检索与回答
  |-- query_data       -> MySQL 查询
  `-- no tool          -> 后端对内容问题执行强制检索兜底
  |
  v
工具结果回传给 LLM
  |
  v
生成最终答案，保存到会话
```

Agent 最多执行 5 轮，避免错误工具调用形成无限循环。同步接口返回 JSON，流式接口使用 SSE 返回会话、工具、文本和结束事件。

## 知识工具

`search_knowledge` 用于制度、流程、教程以及上传文档中的事实和数字：

1. 问题生成 embedding。
2. Chroma 返回相似 chunk。
3. 过滤明显不相关的结果。
4. LLM 只依据资料生成回答。
5. 返回实际使用的来源文件。

## 数据工具

`query_data` 当前用于演示对 `orders` 数据的自然语言查询。只有超级管理员可查询全局授权业务表；部门管理员和普通员工只能查询 `scoped_orders`，后端通过参数化 CTE 将它绑定到当前用户部门，模型不能直接访问完整 `orders` 表。

服务端只允许单表查询，并拒绝 JOIN、子查询、UNION、注释和其他表名。超级管理员受 `NL2SQL_ALLOWED_TABLES` 白名单限制；其他角色进一步只能访问按登录用户部门过滤后的 `scoped_orders`。

这仍不是完整生产方案：数据库连接目前还是开发用账号，下一阶段还要增加只读账号、数据库视图和更严格的字段级权限。

## 权限原则

- 身份和角色由后端 JWT 依赖解析，不能依赖前端隐藏按钮。
- 会话按 `user_id` 隔离，其他用户的会话返回 404。
- 检索前由后端把知识库 ACL 转换为授权 `document_id`，Chroma 只查询这些文档。
- 知识库支持私有、同部门、全员和显式成员授权；模型不能扩大检索范围。
- 部门管理员只能管理本部门知识库，用户和角色管理仅限 `super_admin`。
- 数据权限必须在查询执行前生效，不能查询后再过滤。
