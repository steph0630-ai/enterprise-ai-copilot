# Agent 流程

Agent 的核心是"①思考 → ②行动 → ③观察"的循环，直到能够回答用户的问题。

## 循环流程

```
用户提问 → Agent 收到
        ▼
① 思考：LLM 判断 "知识问题还是数据问题？"
        ▼
② 行动：决定调用工具
        · 知识类 → 调 RAG 工具
        · 数据类 → 调 SQL 工具
        ▼
工具返回结果（文档片段 / 数据库数字）
        ▼
③ 观察：LLM 看结果 "够不够回答？还要不要再调？"
        ├── 够 → 整理成自然语言回答，返回给用户
        └── 不够 → 回到①重新思考（或反问用户澄清）
```

## 多步示例

**用户："我部门上个月订单里，卖得最好的前 3 款产品是哪些？"**

| 轮次 | ①思考 | ②行动 | ③观察 |
| --- | --- | --- | --- |
| 第 1 次 | 数据问题 | 调 SQL：按产品分组 SUM 金额，排前 3 | 拿到 3 款产品 + 金额 |
| 第 2 次 | 结果够了 | 不调工具，直接整理 | 返回："A、B、C..." |

> 有的问题一次就够，有的要多次循环——Agent 自己判断是否继续。

## 工具判定规则

| 问题问的是 | 答案藏在 | 走哪条路 |
| --- | --- | --- |
| 是什么 / 怎么做（政策、流程、制度） | 文档 | RAG |
| 是多少 / 几笔 / 哪个部门（数字、订单） | 结构化数据表 | SQL |

## 权限过滤（关键）

- 生成 SQL 时**强制拼上** `WHERE department = 当前用户部门`，再查 MySQL。
- 普通员工：只能查自己部门；管理员：查全部。
- **原则**：权限在数据源头拦，不能等数据出来后在前端藏。
