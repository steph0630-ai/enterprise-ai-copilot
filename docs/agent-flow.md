# Agent 流程

## 工具循环

```text
用户问题
  |
  v
LLM 判断是否调用工具
  |-- search_knowledge -> RAG 检索与回答
  |-- query_data       -> MySQL 查询
  `-- no tool          -> 后端对内容问题执行强制检索兜底
  |
  v
工具结果回传给 LLM
  |
  v
生成最终答案，保存到会话
```

Agent 最多执行 5 轮，避免错误工具调用形成无限循环。同步接口返回 JSON，流式接口使用 SSE 返回会话、工具、文本和结束事件。

## 知识工具

`search_knowledge` 用于制度、流程、教程以及上传文档中的事实和数字：

1. 问题生成 embedding。
2. Chroma 返回相似 chunk。
3. 过滤明显不相关的结果。
4. LLM 只依据资料生成回答。
5. 返回实际使用的来源文件。

## 数据工具

`query_data` 当前用于演示对 `orders` 数据的自然语言查询。模型生成 `SELECT`，后端负责执行前校验和部门限制。

Day 26 已增加第一道服务端边界：只允许单表 `orders`，拒绝 JOIN、子查询、UNION、注释和其他表名。这样即使模型生成了 `SELECT`，也不能把用户表、文档表等变成可读取目标。

这仍不是完整生产方案：数据库连接目前还是开发用账号，下一阶段还要增加只读账号、数据库视图和更严格的字段级权限。

## 权限原则

- 身份和角色由后端 JWT 依赖解析，不能依赖前端隐藏按钮。
- 会话按 `user_id` 隔离，其他用户的会话返回 404。
- 管理接口要求 `admin` 或 `super_admin`。
- 数据权限必须在查询执行前生效，不能查询后再过滤。
